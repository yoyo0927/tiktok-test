# Live Reactions · AR

这是面向 TikTok LIVE 场景的浏览器 AR 原型。微笑逐渐带出五角星雨和朦胧光环，大笑时星雨隐去，双色烟花一轮轮绽放，伴随渐变圆环、白色闪片、五角星、旋转彩带和几何线框。花瓣和碎粒撞上头部时会弹出同色小星。

## 在线演示（Live Demo）

**[打开 Live Reactions · AR](https://yoyo0927.github.io/tiktok-test/)**

1. 用电脑或手机浏览器打开演示，点击「开启摄像头」，在浏览器提示中选择允许。
2. 让整张脸进入画面。微笑触发星雨，张嘴大笑触发烟花。点击「手机竖屏」可切换到 9:16 画面。横屏每轮可比竖屏多放 2–3 朵烟花。
3. 想跳过摄像头直接查看效果，可切到「调试」，点击「预览星雨」或「试放烟花」。

摄像头画面在浏览器本地处理，页面仅请求摄像头权限。首次开启时，浏览器需要加载追踪模型和 WebAssembly 文件。

## 本地运行

需要 Node.js 22.12+（22 LTS）或 24+。首次启动或构建需要访问 Google 的模型下载地址。

```sh
npm ci
npm run dev
```

打开终端显示的 localhost 地址即可体验。用手机测试摄像头时，可直接打开上面的 HTTPS 演示链接。

```sh
npm test        # 状态机、坐标投影、碰撞和性能档位
npm run build   # TypeScript 检查与生产构建，输出到 dist/
npm run preview # 本地预览生产构建
```

## 验证与现场验收

生产构建和自动测试已通过。线上演示已在 Chrome 的桌面与模拟手机视口中验证，覆盖 HTTPS、模拟摄像头启动与关闭、模型资源加载和烟花试放。真人表情识别和头部碰撞按以下步骤用实际摄像头验收。

1. 开启摄像头并切到「调试」。左右移动、轻微歪头，再切换「手机竖屏」，观察青色虚线椭圆是否随头部移动并与镜像画面对齐。
2. 保持自然表情，再微笑约半秒，检查状态是否从 `neutral` 切到 `smile`，星雨是否逐渐出现。保持嘴角自然并单独张嘴，检查是否误触发烟花。
3. 张嘴大笑，检查状态是否切到 `laugh`、星雨是否淡出以及烟花是否绽放。维持大笑时，烟花以至少 1.05 秒的间隔续放。回到微笑后，观察烟花散尽时星雨是否恢复。
4. 点击「试放烟花」，观察花瓣撞到头部时，小星是否从青色虚线边缘弹开。左右移动头部再试一次。抬手经过烟花区域，观察特效是否被人物轮廓遮挡。
5. 切回「演示」，确认椭圆和数据面板隐藏。关闭摄像头后再开启，检查设备可以重新使用。

## 表情识别

React 和 TypeScript 管理界面与模块，Vite 构建静态站点。MediaPipe Face Landmarker 以 `VIDEO` 模式追踪一张脸，优先使用 GPU，初始化失败时改用 CPU。

`Smile` 取 `mouthSmileLeft` 与 `mouthSmileRight` 的均值。张嘴分数由 `jawOpen`（55%）与归一化唇间距（45%）组成。调试面板的 `Laugh` 显示两个平滑分数的较小值，状态机使用各自的阈值。

| 状态 | 进入 | 保持条件 |
| --- | --- | --- |
| `smile` | Smile ≥ 0.32 | Smile ≥ 0.22 |
| `laugh` | Smile ≥ 0.3994 且张嘴 ≥ 0.319 | Smile ≥ 0.2994 且张嘴 ≥ 0.229 |

表中阈值对应默认滑块设置（微笑灵敏度 60，大笑灵敏度 82）。Smile 超过 0.60 时，大笑所需的张嘴阈值会进一步下调，最多下调 0.065。输入经过 75 ms 时间常数的指数平滑。状态切换需要至少 3 次连续有效观测，并满足 90–150 ms 的确认时长。超过 250 ms 未检测到人脸时，清除碰撞体并恢复 `neutral`。

## 头部与粒子碰撞

额头、下巴和两颊关键点经过与视频 `object-fit: cover` 相同的缩放、居中裁剪和镜像变换。由关键点估计带旋转的椭圆，渲染循环平滑更新中心、尺寸和角度，并计算头部平移速度。

所有花瓣和部分碎粒从各自的烟花爆心飞出并参与碰撞。包围盒先剔除远处粒子，再把移动线段变换到椭圆局部坐标，计算首次接触，减少高速穿透。命中时花瓣与拖尾立即消失，常规档最多弹出 7 颗同色小五角星，降级档最多 5 颗。小星从头部碰撞轮廓的触点向外偏移 2.5 像素生成，向外散开减速，在约 0.40–0.58 秒内淡出。少量仍在衰减的花瓣会在可见拖尾的末端闪出一次小炸花。轮廓是二维近似，侧脸、大幅转头和遮挡会影响贴合。

渲染器用 Pose Landmarker Lite 的人物分割遮罩和头部椭圆裁去星雨、烟花与拖尾中遮住人物的部分。反弹小星在人物遮罩之后绘制，并裁掉进入头部椭圆的部分，使碰撞反馈能在轮廓边缘立即出现。分割结果暂不可用时，用姿态关键点估算躯干和四肢。遮罩和摄像头共用居中裁剪与镜像坐标。调试面板里的花瓣粗细即时生效，花瓣数量在绽放时生效，性能降级时会减少实际发射数量。

横屏每轮最多绽放 8 朵烟花，竖屏最多 5 朵。性能降级时，横屏和竖屏分别最多绽放 6 朵和 4 朵。大笑和「试放烟花」使用同一规则。

同一轮的每朵烟花使用不同的双色搭配，爆心有向外扩散的渐变圆环，花瓣间有白色点状闪片。花瓣飞出后约 0.92–1.28 秒淡出，尾端小炸花约 0.32–0.42 秒淡出。爆点避开头部和 Pose Landmarker Lite 从肩、髋及可见四肢关键点估算的身体区域。姿态模型在摄像头启动后异步加载，暂时缺少关键点时按头部估算上半身，画面没有足够空间时跳过对应烟花。烟花绽放时星雨和光环在约 0.12 秒内完全隐去，烟花散尽后随微笑恢复。滑块调整保存在当前浏览器中，刷新后可继续使用。

## 性能与取舍

- `requestAnimationFrame` 负责 Canvas 2D，物理更新使用秒为单位的 `deltaTime`。人脸识别仅对新视频帧推理，常规与降级档上限约为 18 / 12 Hz。手机开启摄像头后，特效画布的像素预算约为 26 万，性能降级时约为 18 万。摄像头画面、全宽 9:16 布局和粒子坐标沿用原有尺寸，降级时特效边缘可能略软。人脸推理耗时较高时，推理频率可降到约 10 Hz。调试面板分别显示人脸推理和人体分割的耗时。
- 对象池预分配 780 个粒子，星雨同屏最多 300 颗。常规档下，主烟花默认生成 120 片花瓣，小烟花按大小减少花瓣数量。碰撞产生的小星和尾端小炸花同屏分别最多 96 颗和 24 处。花瓣拖尾使用固定长度的位置缓存。
- 星雨和火束的柔光使用预先生成的光晕贴图。FPS 连续两个统计窗口低于 46 时，降低星雨发射率和火束数量，减少副花、碎粒及装饰粒子，缩短拖尾。桌面端和无摄像头预览的 Canvas DPR 上限从 1.75 降到 1.25。连续四个窗口达到 55 FPS 后恢复。
- MediaPipe 的视频调用同步执行。桌面端姿态与分割最多约 10 次/秒，降级时约 5 次/秒。手机等以触摸为主要输入的设备将姿态输入的长边缩至最多 320 像素，并按推理耗时将更新间隔调到 250–500 毫秒。若连续三次人体分割各耗时至少 24 毫秒，本次摄像头会话改用按头部位置估算的身体范围，调试面板显示「已简化」。此时手臂和轮廓边缘的遮挡较粗略，重新开启摄像头会重新测量。
- 人脸模型约 3.8 MB，姿态模型约 5.8 MB，浏览器另外下载匹配能力的 WASM 版本（文件原始大小约 11 MB）。资源在点击开启后才加载。

## GitHub Pages 部署

推送到 `main` 后，GitHub Actions 使用 Node.js 24 安装依赖并构建，在 `/tiktok-test/` 路径发布 `dist/`。也可以在 Actions 页面查看发布结果或手动重新发布。[部署配置](.github/workflows/pages.yml) · [部署记录](https://github.com/yoyo0927/tiktok-test/actions/workflows/pages.yml)

构建时，准备脚本从锁定的 npm 依赖复制 WASM，并下载和校验人脸与姿态模型。模型和 WASM 随演示同源发布，无需配置环境变量。
